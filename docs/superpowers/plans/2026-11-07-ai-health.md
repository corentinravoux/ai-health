# ai-health Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Linux desktop app that live-monitors a local llama.cpp LLM (tokens/s, VRAM, RAM, GPU, processes and their flags) and, on demand, explores a GGUF model as an AI architecture diagram with a complete weight view and a GPU/CPU placement overlay.

**Architecture:** A Python backend (stdlib `ThreadingHTTPServer` on `127.0.0.1`) owns a 1 Hz sampler thread (NVML + psutil + llama-server HTTP probes) and an explorer service (gguf-py, mmap, numpy). It serves JSON, an SSE stream and a no-build static front (HTML/CSS/ES modules, vendored uPlot, hand-drawn SVG diagram). pywebview opens a native GTK/WebKit2 window on that URL; `--browser` serves the same UI to a normal browser.

**Tech Stack:** Python 3.14, `nvidia-ml-py`, `psutil`, `numpy`, `gguf` (editable from `~/Software/llama.cpp/gguf-py`), `pywebview` (GTK backend, system PyGObject), pytest; vanilla JS ES modules, uPlot (vendored), woff2 fonts (vendored).

**Spec:** `docs/superpowers/specs/2026-11-07-ai-health-design.md`

### llama.cpp facts (verified in `~/Software/llama.cpp` on 2026-11-07)

- `-ngl/--gpu-layers/--n-gpu-layers N|auto|all`; default `auto` (= -1); `all` = -2; `--fit on|off`, default **on** (adjusts unset params to fit device memory).
- Offload rule (`src/llama-model.cpp:1766`): `i_gpu_start = max(n_layer + 1 - ngl, 0)`; repeating layer `il` is on GPU iff `il >= i_gpu_start`; the output layer counts as index `n_layer` (on GPU iff `ngl >= 1`); negative ngl ⇒ `n_layer + 1` (everything). The **input layer (`token_embd`) is always CPU**.
- `--cpu-moe` ⇒ regex `\.ffn_(up|down|gate|gate_up)_(ch|)exps` → CPU. `--n-cpu-moe N` ⇒ `blk\.{i}\.ffn_(up|down|gate|gate_up)_(ch|)exps` → CPU for `i < N`. `--n-cpu-ffn N` ⇒ `blk\.{i}\.ffn_(up|down|gate)\.` → CPU for `i < N`. `-ot "re=BUF,re2=BUF"` regex-search on tensor names (`CPU`, `CUDA0`, …); first match wins.
- Server: `/health`, `/props`, `/slots` (default on, `--no-slots` disables; per slot `n_ctx`, `is_processing`, `next_token.n_decoded`), `/metrics` only with `--metrics`. Router mode (no `-m`) needs `?model=` on `/metrics` and `/props`. Metric names: `llamacpp:prompt_tokens_total`, `llamacpp:prompt_seconds_total`, `llamacpp:tokens_predicted_total`, `llamacpp:tokens_predicted_seconds_total`, `llamacpp:requests_processing`, `llamacpp:requests_deferred`, `llamacpp:n_tokens_max`.
- Flags may also come from env vars `LLAMA_ARG_*` (e.g. `LLAMA_ARG_N_GPU_LAYERS`, `LLAMA_ARG_N_CPU_MOE`, `LLAMA_ARG_ENDPOINT_METRICS`, `LLAMA_ARG_CTX_SIZE`, `LLAMA_ARG_PORT`), readable from `/proc/<pid>/environ` for the user's own processes. CLI wins over env.

## Review Focus

1. **llama-server killed/restarted while monitored** (PID vanishes, counters reset to 0) → no crash, tokens/s never negative, the card shows "stopped", a new PID appears as a new server. Test: Task 5 `test_counter_reset_is_not_negative`, Task 8 `test_process_disappears_between_samples`.
2. **Server started with `--api-key`** → endpoints return 401 → card shows "auth required (--api-key)", process/VRAM data still shown. Test: Task 6 `test_probe_401_reports_auth`.
3. **Tensor whose quant type gguf-py cannot dequantize** (e.g. IQ*, MXFP4, TQ*) or a 150k×4096 embedding → metadata still shown; inspector says "dequantization not available for <TYPE>" or "sampled N of M rows". Test: Task 12 `test_unsupported_qtype_returns_reason`, `test_large_tensor_is_row_sampled`.
4. **Another web page in the user's browser calling `http://127.0.0.1:<port>/api/model/open`** (CSRF / DNS rebinding) → 403. Test: Task 9 `test_api_rejects_missing_token`, `test_api_rejects_foreign_host`.
5. **No NVIDIA GPU / NVML init fails / no per-process figures** → monitor still runs with RAM/CPU/processes; GPU panel says "GPU unavailable: <reason>"; VRAM bar falls back to `nvidia-smi`, then "unattributed". Test: Task 3 `test_nvml_init_failure_returns_unavailable`, `test_falls_back_to_nvidia_smi`.

Rules (from the verified llama.cpp facts in Global Constraints):
- `token_embd` → CPU always. Layer `il` GPU iff `il >= max(n_layer + 1 - ngl, 0)`; output tensors (`output`, `output_norm`) GPU iff `ngl >= 1`. `"all"` ⇒ `ngl = n_layer + 1`.

If `vram_free` is None → assume all-GPU, `estimated True`.
- KV: `2 × n_layer_attn × ctx × n_head_kv × head_dim × bytes(type)`, bytes: f32 4, f16/bf16 2, q8_0 1.0625, q4_0 0.5625, q4_1 0.625, q5_0 0.6875, q5_1 0.75, iq4_nl 0.5625; `ctx` default = `ctx_train` when `-c` unset or 0; KV of CPU layers counts as CPU (llama.cpp keeps KV with its layer unless `--no-kv-offload`, add that flag to Task 5's table as `kv_offload: bool`, default True).
